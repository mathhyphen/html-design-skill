# HTML Design Skill

把页面目标转成有鲜明视觉方向、可运行、可检查的响应式 HTML。

一个面向 **Codex** 的中文设计技能，覆盖需求梳理、视觉探索、页面实现与渲染评审。适合希望摆脱千篇一律模板，同时保持内容清晰、交互完整和移动端可用的网页任务。

> A reusable Codex skill for designing distinctive, responsive HTML experiences—from visual exploration to implementation and browser review.

## 它能做什么

- **从目标出发组织内容**：明确受众、主要动作与信息优先级，让页面结构服务实际用途。
- **探索有区别的方案**：需求开放时，先形成 2–3 个结构不同的方向，再选一个实现；简单任务可以压缩流程。
- **把风格落到具体选择**：明确构图、字体层级、配色、间距、素材与动效用途。
- **交付可运行页面**：独立原型默认使用 `index.html`，内嵌简单 CSS / JavaScript；有现成项目时沿用技术栈。
- **检查真实交互与布局**：浏览器可用时检查宽屏、窄屏及关键控件，进行必要修正。
- **清楚说明交付边界**：区分演示与真实服务、已验证与未验证内容，不编造数据或测试结果。

本仓库提供的是供 AI 助手读取的设计工作流，不是前端组件库、网页生成服务或独立运行的应用。实际编码、预览和素材处理能力取决于运行技能的环境。

## 适用场景

| 场景 | 可以交付的内容 |
| --- | --- |
| 产品落地页 | 首屏、价值说明、功能介绍与行动入口 |
| 个人作品集 | 项目展示、个人介绍与清晰的浏览路径 |
| 研究 / 知识专题页 | 长文排版、比较表、图解与可操作的内容切换 |
| 产品界面原型 | 页面布局、交互状态与高保真界面 |
| 现有 HTML 重构 | 信息层级、视觉一致性、响应式布局与交互改进 |

纯文案修改、后端开发或严格像素复刻，一般不需要启动完整设计探索。

## 安装到 Codex

### 方式一：让 Codex 安装

在提供技能安装器的 Codex 环境中，发送：

```text
请安装 https://github.com/mathhyphen/html-design-skill 中的技能。
SKILL.md 位于仓库根目录，安装名称使用 html-design。
```

安装完成后，在下一轮对话中尝试调用 `$html-design`。如果尚未出现，可新建任务或重启当前 Codex 客户端后再检查。

### 方式二：手动安装

需要已安装 Git。以下命令使用 `~/.codex/skills` 作为技能目录；如果你的环境使用自定义 `CODEX_HOME`，请将目标替换为其下的 `skills/html-design`。如果客户端配置了其他技能发现目录，请使用该目录。

**macOS / Linux**

```bash
mkdir -p "$HOME/.codex/skills"
git clone https://github.com/mathhyphen/html-design-skill.git \
  "$HOME/.codex/skills/html-design"
```

**Windows PowerShell**

```powershell
$skillRoot = Join-Path $HOME '.codex\skills'
New-Item -ItemType Directory -Force -Path $skillRoot | Out-Null
git clone https://github.com/mathhyphen/html-design-skill.git (Join-Path $skillRoot 'html-design')
```

安装后的关键结构应为：

```text
html-design/
├── SKILL.md
├── README.md
└── agents/
    └── openai.yaml
```

如果目标目录已经存在，先检查已有版本，避免覆盖自己的修改。只有使用 Git 克隆安装的目录，才适合直接用 `git pull --ff-only` 更新。

## 如何使用

在需求中显式写出 `$html-design`，并尽量给出页面用途、受众、必要内容与交付方式。

### 快速开始

```text
使用 $html-design，为一个科研工具设计中文介绍页。
受众是医学影像研究者，页面需要说明用途、工作流程和使用入口。
风格采用克制的编辑式排版，交付可直接打开的 index.html，适配手机。
```

### 已有内容，制作专题页

```text
使用 $html-design，把下面的研究笔记整理成 HTML 专题页。
突出核心结论、方法比较和局限，保留提供的来源链接。
正文要适合长时间阅读，加入有实际作用的展开与筛选交互。
```

### 改进现有页面

```text
使用 $html-design，检查并改进当前项目的首页。
沿用现有技术栈与品牌色，重点优化信息层级、移动端布局和主操作入口。
实现后检查宽屏与窄屏渲染，并说明修改内容和验证结果。
```

### 希望先选方向

```text
使用 $html-design，为个人作品集提出三个结构不同的设计方向。
分别给出内容组织、构图、字体和素材使用方案，先让我选择再完整实现。
```

如果没有要求先选方案，技能会根据任务判断推进，不会默认在每一步等待确认。

## 设计流程

1. **确定交付边界**：梳理页面用途、受众、主要动作、必要内容和技术约束。
2. **先发散，再聚焦**：理解真正需要解决的问题，比较方向并选定方案。
3. **写下视觉约束**：将模糊风格要求转成可执行的排版、配色、构图与动效选择。
4. **组织内容与素材**：优先使用真实且适用的材料，让素材帮助理解内容。
5. **实现可运行页面**：完成响应式布局、语义结构、可访问性与交互状态。
6. **依据渲染结果评审**：检查实际页面，通常进行 1–2 轮必要修正。
7. **做减法并交付**：去掉无助于理解或操作的装饰，提供页面入口与验证说明。

完整规则见 [SKILL.md](./SKILL.md)。

## 交付与验收

独立页面通常交付：

```text
index.html          # 页面入口，简单样式与脚本内嵌
assets/             # 可选：图片、视频等必要素材
```

已有项目则遵循其目录结构与技术栈，不要求改成单文件 HTML。

| 检查项 | 关注点 |
| --- | --- |
| 内容层级 | 首屏用途明确，主操作突出，阅读顺序自然 |
| 视觉一致性 | 构图、字体、色彩与素材共同服务页面方向 |
| 响应式布局 | 宽屏与窄屏无非预期溢出、重叠或截断 |
| 交互完整性 | 展示出来的链接、切换、菜单和筛选能够操作 |
| 可访问性 | 键盘可用、焦点可见、表单有标签、对比清晰 |
| 交付透明度 | 说明入口、已验证项目和实际限制 |

浏览器可用时，建议至少检查约 **1440px** 和 **390px** 两个视口；关键布局还应检查中间宽度。缺少浏览器时，进行可执行的代码检查，并明确视觉效果未实测。

## 能力边界

- 不要求为独立展示页额外安装前端框架，也不绑定图片供应商或付费服务。
- 不凭空生成真实数据、客户评价、业绩、素材地址或验证结果。
- 原型中的模拟交互不等于真实后端服务已经接通。
- 制作页面不自动包含部署或公开发布；需要发布时应在任务中明确提出。
- 独立代理评审仅在用户要求或明确允许、且环境支持时使用。
- 研究专题中的事实核查和引用质量仍需单独完成；本技能主要负责设计与页面交付。
